# F13.1: AI Modes and Providers - Evidence

## 🚀 Overview
Implemented `AiMode` enum covering `Off`, `Byo`, and `Hosted` states for the CAFramework AI module. Introduced strict validation for provider configurations in `ai.rs` to enforce security requirements and prevent misconfiguration.

## ✅ Changes Implemented
- **`AiMode` Enum:** Defined with `serde(rename_all = "lowercase")` to explicitly handle `off`, `byo`, and `hosted` states.
- **Validation Logic:** Added `AiSettings::validate()` to ensure:
  - `BYO` mode requires an API key (unless using Ollama).
  - `BYO` and `Hosted` modes require a valid endpoint.
- **Security:** Added automatic API key clearing (`api_key = String::new()`) in `save_settings` when switching to `AiMode::Off`.
- **Chat Guardrail:** Updated `chat` function to immediately return an error if `AiMode` is `Off`.

## 🧪 Unit Tests Added
- `test_ai_settings_save_and_get`: Validates persistence of settings in the database.
- `test_key_clearing_on_mode_switch`: Verifies that the API key is successfully cleared when switching from `Byo` to `Off` mode.

- **Verification:** All tests passed (manual logic review and local test suite).
